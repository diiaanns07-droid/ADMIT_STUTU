# R08 · протокол будущей двойной человеческой разметки реальных сообщений

Статус: подготовлен, НЕ выполнялся. Реальные данные: real_data_NOT_EVALUATED.
Агенты (в том числе R08) не заменяют двух людей-разметчиков; агентская разметка — только synthetic.

## 1. Данные и право
- Источник только с правовым основанием: выгрузка оператора/акимата по запросу либо публичный набор с
  лицензией, допускающей обработку. Не runtime SQLite платформы без согласия авторов, не чаты/утечки, не eOtinish.
- Перед передачей разметчикам: `ml.civic_classifier.text.anonymize` (телефоны, e-mail, ИИН, ссылки) и
  ручная проверка имён и адресов квартир; хранение вне Git, доступ по списку.
- Записать: источник, период, дату выгрузки, основание, число записей, что удалено.

## 2. Выборка
- Не менее 600 сообщений; стратификация по месяцам и районам; доля казахского и смешанного текста — как в потоке.
- Временной split: обучение — ранние месяцы, проверка — последующие; проверочный набор открывается один раз.

## 3. Разметка
- Два разметчика независимо, по `ml/civic_classifier/LABELING_GUIDE.md`, не видят подсказку модели и друг друга.
- Поля: label (6 меток), also_labels, ambiguous, language, комментарий.
- Пилот на 50 сообщениях → уточнение правил (пилот в оценку не входит).

## 4. Согласие и расхождения
- Cohen's kappa по меткам и процент совпадений; таблица расхождений по парам меток.
- Расхождения разбирает третий человек (арбитр); причины кодируются (неясное правило / несколько тем /
  ошибка разметчика / нехватка контекста). Правила меняются только между раундами, с новой версией.
- Если kappa < 0.6 — сначала правила разметки, потом модели.

## 5. Оценка
- Тот же протокол, что в PROTOCOL.md: словарь, logreg, гибрид, гибрид+отказ; per-class/per-language
  precision/recall/F1, матрицы ошибок, покрытие при отказе, уверенные ошибки; интервалы по группам (по
  месяцам/авторам), если их достаточно.
- Калибровку score проводить только на отдельной части реальных данных; до этого score — не вероятность.
- `training_data_status` меняется с `synthetic_demo_only` только после этой проверки; needs_review остаётся
  включённым, пока точность принятых не подтверждена на реальной проверочной выборке.
